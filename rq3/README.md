# RQ3 — โค้ดที่ AI สร้าง ล้มเหลวเงียบในรูปแบบใด และเกิดซ้ำข้ามโมเดลไหม

**สถานะ: เก็บแล้ว 3 ครั้ง จาก 2 โมเดล** — Opus 5 สองรอบ (5/10 · 7/10) · ChatGPT หนึ่งรอบ (10/10)

## 🔴 RQ3 ตอบเป็นรูปแบบ ไม่ใช่อัตรา — อ่านก่อนใช้ตัวเลขจากที่นี่

ทะเบียนบั๊ก `H01–H31` ใน `FAULTS.md` อ้างเป็นอัตราไม่ได้ เพราะจดเฉพาะที่สังเกตเห็น
และไม่มีตัวหารว่า "จากกี่โอกาส"

**RQ3 มีตัวหาร แต่ยังอ้างเป็นอัตราไม่ได้อยู่ดี** — โจทย์ 10 ข้อนี้**ออกแบบมาเล็งกับดัก
ที่รู้อยู่แล้ว** ตัวหารจึงเป็นจำนวนโจทย์ที่ผู้วิจัยเลือกเอง ไม่ใช่โอกาสที่เกิดในงานจริง
**เพิ่มจำนวนโจทย์ไม่ช่วย** เพราะปัญหาอยู่ที่วิธีเลือกโจทย์ ไม่ใช่ขนาดตัวอย่าง

สิ่งที่ชุดนี้ตอบได้หนักแน่นคือ **ล้มเหลวรูปแบบใด · รูปแบบไหนเกิดซ้ำข้ามโมเดล ·
ผลนิ่งไหมเมื่อถามซ้ำ** (ดู `DECISIONS.md` D20)

> ⚠️ **ต้องเก็บ 2 รอบต่อโมเดล** — Opus 5 ได้ 5/10 กับ 7/10 บนโจทย์เดียวกันเป๊ะ
> รอบเดียวพิสูจน์แล้วว่าไม่นิ่ง และรอบสองเปลี่ยนข้อสรุปของงานจริง (E38)

## วิธีให้คะแนน — รันจริง ไม่ดูรูปแบบ

ตัวให้คะแนนเอา SQL ไป **รันบนฐานข้อมูลจริง** แล้ววัดผลเทียบ exact search
ไม่ได้ match ข้อความว่า "มี `ORDER BY` ไหม" เลย

เพราะ Q03 พิสูจน์แล้วว่า SQL ที่ถูกรูปทุกอย่าง (`WHERE` + `ORDER BY` + `LIMIT`)
ยังคืน **0 แถว** ได้ — ตัวให้คะแนนที่ดูรูปแบบจะบอกว่าผ่าน

**เกณฑ์หลักคือความครบของแถว** (ขอ k ได้ k ไหม) เหมือนที่ตัวตรวจ Q03/Q06/L02 ใช้อยู่แล้ว
เพราะไม่ต้องรู้เฉลยและตัดสินไม่ผิดฝั่ง · `recall` รายงานเป็นข้อมูล

> **ทำไมไม่ใช้ recall เป็นเกณฑ์:** วัดแล้วพบว่าคำตอบที่จูนเต็มที่
> (`ef_search=400` + `iterative_scan` + `work_mem 16MB`) **ยังได้แค่ 0.90** ที่ filter 1%
> ตั้งเกณฑ์ 1.00 จะตีคำตอบที่ถูกต้องว่าผิด

## วิธีรัน

```bash
docker compose exec -T db psql -U lab -d faultlab -f /sql/rq3_setup.sql
python scripts/rq3_score.py rq3/answers/<ชื่อชุด>
docker compose exec -T db psql -U lab -d faultlab -f /sql/rq3_teardown.sql
```

**ต้องเก็บกวาดทุกครั้ง** — สภาพสะอาดที่ทั้งโปรเจคใช้อ้างอิงคือ *ไม่มี vector index ค้าง*
ถ้าปล่อย index ของ RQ3 ไว้ `scripts/audit.py` จะฟ้องทุกครั้ง และคนอ่านจะแยกไม่ออกว่า
เป็นของ RQ3 หรือเป็นรอบทดลองที่ตายกลางคัน

`rq3_setup.sql` สร้างตาราง `documents` ที่หน้าตาเหมือนตารางในแอปจริง
**พร้อม HNSW index ค่าเริ่มต้น** — ถ้าไม่มี index ทุก query จะเป็น exact search
แล้วผ่านหมดโดยไม่มีความหมาย (ตัวให้คะแนนจะปฏิเสธที่จะรันถ้าไม่มี index)

## ยังขาดอะไร

**คำตอบจากโมเดลจริง** — ต้องมาจากโมเดลที่ **ไม่เคยอ่าน repo นี้**

`CLAUDE.md` ระบุกับดักทั้ง 12 ข้อพร้อมทางแก้ · โมเดลที่เห็นไฟล์นั้นจะตอบถูกหมด
แล้ววัดไม่ได้อะไรเลย · และผู้ช่วยที่เขียนโปรเจคนี้ก็เป็นผู้ถูกทดลองไม่ได้ด้วยเหตุผลเดียวกัน

**วิธีเก็บคำตอบ**

1. เปิดแชทใหม่กับโมเดลที่จะทดสอบ (ห้ามให้เห็น repo นี้)
2. เปิด **[`prompts_copypaste.md`](prompts_copypaste.md)** — วางบล็อกสคีมาก่อน แล้วถามทีละข้อ
3. **ห้ามใบ้เรื่อง index หรือ tuning** และห้ามถามย้ำว่า "แน่ใจนะ"
4. เก็บ SQL ที่ได้เป็น `rq3/answers/<ชื่อโมเดล>/P01.sql` ... `P10.sql`
5. รัน `python scripts/rq3_score.py rq3/answers/<ชื่อโมเดล>`

ผลจะถูกเขียนลง `results/rq3_<ชื่อโมเดล>.txt`

> เมื่อได้ผลจากโมเดลจริงแล้ว ให้สรุปลง `results/rq3_ai_traps.txt`
> แล้วแก้ `scripts/audit_baseline.json` ข้อ 5 เป็น `done: true`
> พร้อมแก้ตารางของส่งมอบใน `CLAUDE.md` — **audit จะ FAIL ถ้าแก้ไม่ครบ**
