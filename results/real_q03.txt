**บนข้อมูลจริงอาการเริ่มเร็วกว่า แต่ถึงศูนย์ช้ากว่า**
  เริ่มขาด : จริงที่ 20% · สังเคราะห์ที่ 10%
  ถึงศูนย์ : จริงที่ 0.5% · สังเคราะห์ที่ 2%

**สิ่งที่เหมือนกันและสำคัญกว่า:**
  - ใช้ index ทุกกรณี (uses_index = true ทุกแถว)
  - **ไม่มี error สักครั้ง**
  - buffers นิ่งที่ 530 ตั้งแต่ 20% ลงไป ทั้งที่ผลลัพธ์ลดจาก 6 เหลือ 0

       ทีมที่เฝ้าดู I/O จะไม่เห็นอะไรผิดปกติเลย (สังเคราะห์นิ่งที่ 977 เหมือนกัน)

**ข้ออ้างหลักยืนยันแล้วทั้งสองชุดข้อมูล:**
ทางแก้ที่เอกสารระบุไม่มีข้อไหนทำให้ได้ผลครบ — **ตัวที่ปลดล็อกคือ `work_mem`
ซึ่งเป็นค่าทั่วไปของ PostgreSQL ไม่ใช่ของ pgvector และไม่อยู่ในรายการข้อจำกัด
4 ข้อที่ EVIDENCE.md จดจากเอกสาร**

------------------------------------------------------------------------------
🔴 ถ้อยคำที่ต้องผ่อน
------------------------------------------------------------------------------

  เคยเขียน : "ทางแก้ไม่ทำงานเลย จนกว่าจะแตะค่าที่เอกสารไม่ได้พูดถึง"
  บนข้อมูลจริง: ทางแก้**ช่วยบางส่วน** (1 -> 5 -> 5 -> 13) แต่**ไม่เคยครบ**

  ที่ถูกต้องคือ: **ทางแก้ที่เอกสารระบุไม่เพียงพอ ไม่ว่าจะทำครบทุกข้อ**
                 ผลจะครบก็ต่อเมื่อเพิ่ม work_mem ซึ่งเอกสารไม่ได้พูดถึง

------------------------------------------------------------------------------
⭐ ผลใหม่ที่คมกว่าเดิม — max_scan_tuples ไม่ได้อะไรเลยทั้งสองชุด
------------------------------------------------------------------------------

  ขั้น 2 -> 3 (max_scan_tuples เพิ่ม 10 เท่า)
      สังเคราะห์  0 -> 0   buffers 1,743 -> 1,743 (เท่ากันเป๊ะ)
      จริง        5 -> 5   buffers   873 ->   873 (เท่ากันเป๊ะ)

**buffers ไม่ขยับแม้แต่บล็อกเดียวทั้งสองชุดข้อมูล** = พารามิเตอร์นี้ไม่มีผลใดๆ
ในสถานการณ์นี้ ทั้งที่เอกสารระบุไว้เป็นหนึ่งในทางแก้

-> เป็นข้อค้นพบที่**แข็งขึ้น**จากการทดสอบข้ามชุดข้อมูล ไม่ใช่อ่อนลง
