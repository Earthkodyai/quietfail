------------------------------------------------------------------------------
🔴 ข้อที่ถูกหักล้าง — "คำเตือนออกกับกรณีที่ดีที่สุด"
------------------------------------------------------------------------------

บนสังเคราะห์ A ได้ 1.0000 = **ดีที่สุด**  -> สรุปว่าคำเตือนออกผิดที่
บนข้อมูลจริง A ได้ 0.4520 = **แย่เป็นอันดับสอง** -> **คำเตือนออกถูกที่**

และข้อความ DETAIL "This will cause low recall"
  บนสังเคราะห์ **เป็นเท็จ** (A ได้ 1.0000)
  บนข้อมูลจริง **เป็นจริง** (A แย่เป็นอันดับสอง)

CLAUDE.md เตือนเรื่องนี้ไว้เองแล้วว่า A ได้ 1.0000 เพราะ corpus เรียง id สลับกลุ่ม
50 แถวแรกจึงครบ 50 กลุ่มพอดี — **คุณสมบัติของข้อมูลชุดนั้น ไม่ใช่กฎทั่วไป**
ตอนนี้พิสูจน์แล้วว่าใช่ ด้วยข้อมูลคนละชุด

------------------------------------------------------------------------------
⭐ ข้อที่รอด — "ความเป็นตัวแทนสำคัญกว่าจำนวนแถว"
------------------------------------------------------------------------------

**คู่ที่คุมจำนวนแถวเท่ากัน 1,000 ต่างแค่กระจาย vs กระจุก:**

  B กระจาย  0.5974   ·  query ที่ได้ 0 อัน  44 จาก 1,000
  D กระจุก  0.4151   ·  query ที่ได้ 0 อัน 104 จาก 1,000

  -> กระจุกแย่กว่า 31% ทั้งที่จำนวนแถวเท่ากันเป๊ะ

**และ A (50 แถวกระจาย) ยังชนะ D (1,000 แถวกระจุก)** 0.4520 vs 0.4151

  -> "จำนวนแถวมากกว่าไม่ได้แปลว่าดีกว่าอัตโนมัติ" **ยังเป็นจริง**
     แต่ขนาดของผลยุบลงมาก: สังเคราะห์ชนะ 4.4 เท่า · จริงชนะ 9%

------------------------------------------------------------------------------
🔴 ทิศทางของ "ข้อมูลมากขึ้น" กลับด้านทั้งแถว
------------------------------------------------------------------------------

  สังเคราะห์  A 1.0000 -> B 0.8798 -> C 0.7682   ยิ่งมากยิ่งแย่ (กลับหัว)
  จริง        A 0.4520 -> B 0.5974 -> C 0.6653   ยิ่งมากยิ่งดี  (ตามที่เอกสารบอก)

**บนข้อมูลจริง วิธีที่เอกสารแนะนำ (build ตอนข้อมูลครบ) ได้ผลดีที่สุด**
ซึ่งตรงข้ามกับที่วัดได้บน corpus สังเคราะห์

------------------------------------------------------------------------------
⭐ ผลใหม่ที่ corpus สังเคราะห์มองไม่เห็น — A นิ่งสนิท 100%
------------------------------------------------------------------------------

  ช่วงของ recall จาก 5 build:
      A  0.0000   <- ไม่ขยับเลยแม้แต่นิดเดียว
      B  0.0495
      C  0.0490
      D  0.0225

**กลไก:** A มี 50 แถว แต่ lists = 100 -> แถวน้อยกว่าจำนวนกลุ่มที่ขอ
k-means จึงไม่มีอะไรให้สุ่ม แต่ละแถวกลายเป็นจุดศูนย์กลางของตัวเอง = **กำหนดได้แน่นอน**

-> **เงื่อนไขเดียวกับที่ pgvector เตือน คือเงื่อนไขเดียวที่ผล reproduce ได้ 100%**
   ความไม่นิ่งของ I04 หายไปพอดีตรงจุดที่เอกสารบอกว่าอย่าทำ

  ยังพูดได้ : NOTICE ออกเฉพาะเมื่อ rows < lists เท่านั้น จึงเงียบสนิทกับกรณี

  พูดไม่ได้ : "DETAIL เป็นเท็จ" — เป็นจริงบนข้อมูลจริง

ซึ่งเป็นกรณีที่แย่ที่สุดในทั้งสองชุดข้อมูล (D ได้ query ที่ได้ 0 อัน มากที่สุดทั้งคู่)
