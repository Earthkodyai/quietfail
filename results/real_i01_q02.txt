------------------------------------------------------------------------------
I01 — opclass ไม่ตรงกับ operator
------------------------------------------------------------------------------

                          สังเคราะห์              จริง
  ไม่มี index              (ค่าฐาน)          23,388 buffers · recall 1.0000
  opclass ผิด (l2)        ไม่ใช้ index      23,388 buffers · recall 1.0000  <- เท่ากันเป๊ะ
  opclass ถูก (cosine)    ใช้ index            473 buffers · recall 0.9930

**buffers ของ "opclass ผิด" เท่ากับ "ไม่มี index เลย" ทุกบล็อก (23,388 = 23,388)**
= หลักฐานตรงว่า planner ไม่แตะ index นั้นเลย ไม่ใช่แค่ใช้น้อยลง

**I01 คือภาพสะท้อนกลับด้านของ Q01 — ยืนยันแล้วบนข้อมูลจริง**

  Q01  index ถูกใช้      -> เร็วขึ้น 49 เท่า  แต่ recall ตกเหลือ 0.9930
  I01  index ไม่ถูกใช้    -> recall สมบูรณ์ 1.0000  แต่ไม่เร็วขึ้นเลย

ทั้งคู่**ไม่มี error** และดูปกติจากฝั่งผู้ใช้ · ทีมที่เฝ้าดู recall จะไม่เห็น I01
ทีมที่เฝ้าดู latency จะไม่เห็น Q01

------------------------------------------------------------------------------
Q02 — รูปแบบ query ที่ทำให้ index ใช้ได้หรือใช้ไม่ได้
------------------------------------------------------------------------------

  เขียนแบบ                        ใช้ index  ได้กี่แถว   buffers
  1. ORDER BY <=> ASC + LIMIT        ✅         10        473
  2. WHERE <=> < 0.5 อย่างเดียว       ❌        151     23,388
  3. WHERE + ORDER BY + LIMIT        ✅         10        475
  4. ORDER BY <=> DESC               ❌         10     23,388
  5. ORDER BY (<=>) + 0              ❌         10     23,388
  6. ORDER BY ไม่มี LIMIT             ❌    100,000     23,388

**รูปแบบที่ใช้ index ได้ 2 จาก 6 เหมือนกันเป๊ะกับ corpus สังเคราะห์**
และ**ตัวที่ใช้ไม่ได้ทั้ง 4 แบบ ให้ buffers เท่ากันหมด** = ตกไปเป็น seq scan ทั้งหมด

  ช่องว่าง buffers   สังเคราะห์ 21 เท่า (20,005 / 947)
                     จริง       49 เท่า (23,388 / 473)

**ข้อสรุปเชิงกลไกเหมือนกันทุกประการ:**
  - `WHERE` ไม่ใช่ตัวปัญหา — แถวที่ 3 มีทั้ง WHERE และใช้ index ได้
  - ตัวปัญหาคือ**การขาด `ORDER BY` + `LIMIT`** ตามที่ชื่อ fault ถูกแก้ไปแล้ว
  - `+ 0` ปิด index ได้ทั้งสองชุด — ซึ่งเป็นทริกเดียวกับที่ Q03 ต้องใช้บน PG17
    **ทางแก้ของ fault หนึ่ง คือวิธีฉีดของอีก fault หนึ่ง**
  - **ไม่มี error สักรูปแบบเดียว**

ต่างกันเฉพาะเชิงปริมาณ: แถวที่ 2 ได้ 151 แถว (สังเคราะห์ 2,000) เพราะเกณฑ์ 0.5
ตัดข้อมูลคนละสัดส่วนกัน ซึ่งเป็นคุณสมบัติของการกระจายตัว ไม่ใช่ของกลไก
