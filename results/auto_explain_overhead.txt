auto_explain ในโปรไฟล์ fragile เพิ่มต้นทุนให้ทุก query — ไม่ใช่เฉพาะที่ถูก log
==============================================================================
วันที่วัด : 2026-08-01
เหตุ      : ทวน docker-compose.yml และ config/ แล้วพบว่าโปรไฟล์ที่ใช้วัดผล
            ทั้งโครงงานเปิด auto_explain.log_analyze และ log_timing ไว้

config/postgresql.fragile.conf
    shared_preload_libraries = 'pg_stat_statements,auto_explain'
    auto_explain.log_min_duration = 200ms
    auto_explain.log_analyze      = on      <-- ตัวปัญหา
    auto_explain.log_timing       = on      <-- ตัวปัญหา
    auto_explain.log_nested_statements = on

config/postgresql.realistic.conf ก็เปิดเหมือนกัน (log_min_duration = 1s)

------------------------------------------------------------------------------
เอกสาร PostgreSQL 17 พูดถึงเรื่องนี้ไว้ตรงๆ
------------------------------------------------------------------------------

  auto_explain.log_timing:
    "When this parameter is on, per-plan-node timing occurs for **all
     statements executed, whether or not they run long enough to actually
     get logged**. This can have an extremely negative impact on performance."

  -> ค่า log_min_duration = 200ms **ไม่ได้จำกัดต้นทุน** มันจำกัดแค่ว่าจะเขียน log
     หรือไม่ · การจับเวลาต่อ plan node เกิดกับ **ทุก query** อยู่ดี
     เพราะต้องวัดก่อนถึงจะรู้ว่าเกิน 200ms หรือเปล่า

------------------------------------------------------------------------------
วัดจริงในเครื่องนี้ — 4 รอบ
------------------------------------------------------------------------------
qf_corpus 100,000 แถว · 384 มิติ · exact search (ไม่มี index) · 3 query ต่อรอบ
เปลี่ยนเฉพาะ auto_explain.log_analyze / log_timing ระดับ session

  รอบ    auto_explain on    auto_explain off
  ---    ---------------    ----------------
   1          88.8 ms            75.0 ms
   2          89.1 ms            79.2 ms
   3          97.2 ms            85.5 ms
   4          79.2 ms            73.7 ms
  ---    ---------------    ----------------
  เฉลี่ย       88.6 ms            78.3 ms

  **ต้นทุนเพิ่ม 13.1%** และ **on > off ทุกคู่ 4 จาก 4 รอบ**

  ⚠️ query ที่ใช้วัดมี plan node น้อย (Sort + Seq Scan) · query ที่มี plan
     ซับซ้อนกว่าจะได้รับผลมากกว่านี้ เพราะต้นทุนเป็นต่อ node

==============================================================================
กระทบอะไรบ้าง และไม่กระทบอะไร
==============================================================================

🟢 **ไม่กระทบข้อสรุปหลักของโครงงาน**

   กฎเหล็กข้อ 7 บังคับให้ใช้ `buffers` เป็นตัวชี้วัดหลักด้าน I/O ไม่ใช่เวลา
   อยู่แล้ว ตั้งแต่ก่อนพบเรื่องนี้ · buffers เป็นค่าเชิงโครงสร้าง
   **auto_explain ไม่กระทบ buffers เลย**

   ข้อสรุปที่ผูกกับ recall · จำนวนแถว · จำนวน tuple · fingerprint
   ก็ไม่กระทบทั้งหมด

🔴 **กระทบตัวเลขเวลาทุกตัวที่รายงานไว้**

   ตัวเลขเวลาทุกตัวในเล่มวัดใต้เงื่อนไขที่มี auto_explain เปิดอยู่
   จึงสูงกว่าที่ระบบเดียวกันจะทำได้จริงราว 13% (บน query แบบที่วัด)

   **ข้อสรุปที่ใช้เวลาเป็น "การเปรียบเทียบภายใน" ไม่กระทบ** เพราะทุกเงื่อนไข
   ถูกวัดใต้ overhead เดียวกัน เช่น
     - Q04  probes=1 เทียบ probes=10 (ช้ากว่า 2.2 เท่า)
     - Q01  index เร็วกว่า exact กี่เท่า
     - I05  build ช้าลงกี่เท่าเมื่อ spill
     - L02  REINDEX 3.4 วิ เทียบ VACUUM 12.8 วิ

   **ที่ต้องระวังคือการยกตัวเลขเวลาไปเทียบกับระบบอื่น** ซึ่งเล่มไม่ได้ทำอยู่แล้ว
   (กฎเหล็กข้อ 7 และข้อจำกัดข้อ 1 ในบทที่ 6 ระบุไว้ว่าเวลาใช้เทียบภายในเท่านั้น)

==============================================================================
ทำไมถึงตั้งค่าแบบนี้ และควรเปลี่ยนไหม
==============================================================================

  auto_explain มีไว้เพื่อ**เก็บ plan ของ query ที่ช้าโดยอัตโนมัติ** ซึ่งเป็น
  เครื่องมือวินิจฉัยที่ตรงกับธีมของโครงงาน (ความล้มเหลวที่ไม่มี error)
  จึงเป็นการตั้งค่าที่มีเหตุผล **ไม่ใช่ความผิดพลาด**

  🔴 **แต่ไม่เคยถูกบันทึกว่าเป็นเงื่อนไขของการวัด** ซึ่งเป็นช่องว่างจริง
     เพราะผู้ทำซ้ำที่ใช้ค่าปริยายของ PostgreSQL จะได้เวลาต่างจากในเล่ม

  **ไม่เปลี่ยนค่า config** — เปลี่ยนแล้วตัวเลขเวลาทั้งหมดที่บันทึกไว้จะเทียบ
  กับของใหม่ไม่ได้ และข้อสรุปทั้งหมดไม่ได้ผูกกับเวลาอยู่แล้ว
  **สิ่งที่ทำคือบันทึกไว้เป็นเงื่อนไขของการวัด** ในบทสภาพแวดล้อม
